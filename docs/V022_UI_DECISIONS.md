# Project Arranger v0.22 UI Decisions

本文档记录 v0.22 开发前已经拍板的 UI 与 Tutorial 交互决策。后续 agent 实现 UI、Tutorial Engine、Input Adapter、QA 时，应以本文档为准。

## 1. Tutorial 形式

Tutorial 采用真实 UI 上的 Overlay。

- 不在弹窗里复制一套可操作 UI。
- 用户始终操作背后的真实 App UI。
- Overlay 只负责教学面板、轻遮罩、目标高亮、提示和反馈。
- 这样可以避免教程 UI 和真实 UI 状态不同步，也能让用户学到的操作直接对应正式界面。

## 2. Tutorial 面板位置

Tutorial 面板固定在右侧。

- 面板不跟随目标跳动。
- 面板在整个教程中保持稳定位置，让新手用户有固定的信息锚点。
- 主操作区保留给轨道、矩阵、Chord Composer 和 Lead 演奏。

推荐 CSS 约束：

```css
.tutorial-panel {
  width: min(25vw, 360px);
  min-width: 280px;
}
```

面板宽度规则：

- 不超过屏幕宽度的 1/4。
- 1280px 横屏时，面板最多约 320px。
- 1440px 及以上屏幕时，面板最多 360px。
- 主工作区优先，右侧面板不能挤压核心音乐编辑区域。

## 3. Overlay 与目标高亮

Tutorial Overlay 使用轻遮罩和发光描边。

- 背景只轻微压暗，不使用强黑幕。
- 当前目标使用发光描边高亮。
- 目标区域内部保持真实 UI 原样，不被遮暗。
- 目标区域必须保持可点击。
- 任务完成时，高亮可短暂变成绿色，给用户明确正反馈。

推荐视觉方向：

- 高亮描边使用亮青色或电蓝色。
- Glow 轻微、克制，不要过度游戏化。
- 如果目标元素暂时不存在，右侧面板给出引导，例如提示用户先切换到对应轨道或打开对应编辑区。

## 4. 非目标区域交互

教程期间，非目标区域允许点击，但会提醒用户回到当前步骤。

- 不完全锁死界面，避免用户感觉 App 失去响应。
- 用户点击非目标区域时，右侧教学面板显示轻提示。
- 提示语内容后续由完整教程文案提供。
- 关键步骤可以在实现上提高提醒强度，但默认不阻断普通点击。

## 5. 步骤推进方式

教程不会在任务完成后自动跳到下一步。

- 介绍类步骤：主按钮直接显示“下一步”。
- 操作类步骤：操作未完成时，主按钮置灰。
- 用户完成目标操作后：
  - 目标高亮短暂显示完成状态。
  - 右侧面板显示完成反馈。
  - 主按钮变为“下一步”。
- 用户点击“下一步”后才进入下一步。

这样可以让用户有时间看到自己刚才完成的操作，也能听到音乐反馈，不会被系统突然带走。

## 6. 教学面板按钮

右侧教学面板包含以下按钮：

- 主按钮：`开始` / `下一步` / `完成`
- 次按钮：`跳过教程`
- 小按钮或菜单项：`重新开始`

按钮行为：

- 操作未完成时，主按钮置灰，可显示“完成当前步骤后继续”。
- `跳过教程` 进入自由创作模式。
- `重新开始` 默认只重置教程进度，不清空音乐内容。
- 清空作品应作为独立危险操作，不和“重新开始教程”绑定。

## 7. 教程文案配置

教程提示词由用户后续提供完整内容。

实现时不要把文案写死在组件里。所有教学内容应放在教程配置中，UI 只负责展示。

每个教程步骤建议支持：

```js
{
  id: 'perc-kick-1',
  title: '步骤标题',
  prompt: '主提示词',
  hint: '用户点错或未完成时的提示',
  successMessage: '完成后的反馈',
  target: '[data-tutorial-target="perc-kick-step-0"]',
  completion: {
    type: 'perc-hit',
    instrument: 'kick',
    bar: 0,
    step: 0,
  },
}
```

配置原则：

- 组件不决定文案。
- Tutorial Engine 不关心具体措辞，只读取配置。
- 后续替换完整提示词时，优先改 `tutorialSteps` 配置，不改 UI 组件。

## 8. Implementation Notes

后续实现时建议拆成三个层次：

- `TutorialOverlay`：负责遮罩、高亮框和右侧面板渲染。
- `tutorialSteps`：负责步骤顺序、标题、提示词、目标选择器、完成条件。
- `tutorialSlice` / evaluators：负责当前步骤、完成判断、跳过、重新开始和进度恢复。

目标元素应使用稳定属性标记：

```jsx
<button data-tutorial-target="transport-play">
  PLAY
</button>
```

Overlay 根据当前步骤的 `target` 找到真实 DOM 元素，再绘制高亮框。不要通过复制组件来实现教程目标。

## 9. Acceptance Criteria

Tutorial UI 完成后，应满足：

- 右侧教学面板宽度始终不超过屏幕 1/4。
- 真实 UI 可见，目标区域可点击。
- 非目标区域点击不会让 App 卡死，并能给出回到当前步骤的提示。
- 操作类步骤完成后，主按钮变为“下一步”，不会自动跳转。
- 跳过教程后可自由创作。
- 重新开始教程不会清空已有音乐内容。
- 教程文案可以通过配置替换，不需要改组件代码。
